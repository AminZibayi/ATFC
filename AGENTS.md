# AGENTS.md — Technology Forecasting: Additive Manufacturing

## Project Overview

Bibliometric analysis and technology forecasting of Additive Manufacturing using Web of Science publications (126K) and patent data (30K). The pipeline: data collection → NLP preprocessing → LDA topic modeling → trend analysis → Mann-Kendall statistical testing.

## Commands

No test or build commands currently exist. All datasets are pre-processed — scripts folder is empty.

## Pseudo-Monorepo Architecture

This project is a **pseudo-monorepo**: each analysis is a self-contained unit with its own script directory, plot directory, and output directory. This ensures scripts, plots, and outputs are co-located by analysis — not dumped into flat folders.

**Convention:** when creating a new analysis (e.g., "topic_evolution"), create matching directories:

```
scripts/topic_evolution/        # Script(s) for this analysis
plots/topic_evolution/          # Plots generated by this analysis
outputs/topic_evolution/        # Tabular outputs generated by this analysis
```

Never place a script loose in `scripts/` — always nest it under a named subdirectory. Same for `plots/` and `outputs/`.

## Code Style

- Follow existing patterns in `visualize_networks_labeled.py`
- Use pandas for all data manipulation
- Save outputs to `outputs/` or `plots/` — never to `data_source/`
- Prefer xlsx for tabular outputs, png for plots (300 dpi)
- Keep analysis notebooks/scripts self-contained with clear section headers

## Boundaries

- **NEVER modify files in `data_source/`** — these are the raw and pre-processed source datasets
- **NEVER commit large data files** (xlsx, json) to version control
- **NEVER overwrite existing plots** — use versioned filenames or new subdirectories
- Do not install packages without checking what is already available
- Do not re-run topic modeling on data that has already been processed — use existing LDA outputs

## Workflow Guidance

When adding new analyses:

1. **Use existing derived datasets** — topic assignments, trends, and MK results already exist in `data_source/`. Do not recompute from scratch.
2. **Write scripts to `scripts/<analysis_name>/`** — e.g., `scripts/topic_evolution/topic_evolution_streamgraph.py`
3. **Save plots to `plots/<analysis_name>/`** and outputs to `outputs/<analysis_name>/` — matching the script's subdirectory name
4. **Cross-reference both corpora** — publications and patents should be compared, not analyzed in isolation
5. **Reference `rename_mapping.yaml`** if you need to trace back to original filenames

## Available Analyses

These datasets support: topic evolution visualization, emerging/declining topic identification, science-technology linkage, technology life cycle modeling (S-curve, Bass diffusion), citation analysis, co-authorship networks, keyword co-occurrence, interdisciplinary analysis, funding landscape mapping, and Hype Cycle positioning.
